=====================================================
SUBTITLE — VOICE INFORMATION PRESERVATION
=====================================================

subtitle은 voice를 짧은 카피로 요약하는 항목이 아니다.

subtitle은 voice에서 전달하는 핵심 정보를
시청자가 화면만 읽어도 대부분 이해할 수 있도록
보존해서 작성한다.


=====================================================
SUBTITLE INFORMATION RULE
=====================================================

1.
subtitle은 voice의 핵심 의미를 유지한다.

2.
voice에 포함된 다음 정보는 임의로 삭제하지 않는다.

- 핵심 사실
- 원인
- 이유
- 작동 방식
- 행동
- 효과
- 결과
- 수치
- 시간
- 비교
- 조건
- 대상
- 중요한 특징

3.
subtitle의 정보량은 voice의 약 70~90% 수준을 유지한다.

여기서 70~90%는 단순한 글자 수 비율이 아니다.

voice가 전달하는 핵심 정보의 70~90% 이상을
subtitle에서도 전달해야 한다.

4.
voice가

원인 → 결과

구조라면 subtitle에서도
원인과 결과를 모두 유지한다.

5.
voice에 수치가 포함되어 있다면
subtitle에서도 같은 수치를 유지한다.

6.
voice에 조건이나 상황이 포함되어 있다면
subtitle에서도 같은 조건과 상황을 유지한다.

7.
voice의 핵심 효과나 결과를
짧은 감탄사나 한 단어로 대체하지 않는다.

예:

voice:
"구석진 틈새까지 알아서 파고들어
청소 시간이 반으로 줄어듭니다."

금지 subtitle:
"구석진 틈새 순삭"

금지 subtitle:
"청소 끝"

금지 subtitle:
"반으로 줄어듦"

허용 subtitle:
"구석진 틈새까지 알아서 파고들어
청소 시간이 반으로 줄어듭니다."

또는

"구석진 틈새까지 알아서 파고들어
청소 시간을 반으로 줄여줍니다."

8.
voice의 문장을 반드시 그대로 복사할 필요는 없다.

자막에서 읽기 자연스럽도록
조사, 접속어, 반복 표현, 불필요한 수식어는
자연스럽게 다듬을 수 있다.

하지만 핵심 정보가 사라질 정도로
압축해서는 안 된다.

9.
다음과 같은 짧은 표현으로
voice 전체 내용을 대체하지 않는다.

"순삭"
"끝"
"대박"
"콕"
"공감"
"놀랍죠"
"이게 핵심"
"이유는 이것"

10.
subtitle은 voice와 별개의 새로운 카피를
창작하는 항목이 아니다.

voice에서 실제로 말한 내용을 기반으로 작성한다.

11.
HOOK ABSOLUTE RULE

Hook은 설명의 시작이 아니다.
첫 1~2초 안에 시청자의 스크롤을 멈추게 만드는
가장 강한 한 문장이다.

- Hook은 반드시 1문장이다.
- 1~2초 안에 음성으로 전달할 수 있을 정도로 짧게 작성한다.
- 가능하면 10~15자 내외로 작성한다.
- 길어도 20자 안팎을 넘기지 않는다.
- 첫 3~5단어 안에 사건, 결과, 반전, 의외의 사실 또는 강한 궁금증을 배치한다.
- 시대, 장소, 배경, 인물 설명부터 길게 시작하지 않는다.
- "오늘은 ~", "많은 사람들이 ~", "여러분은 알고 계셨나요?" 같은 상투적인 도입을 금지한다.
- 가능한 경우 배경보다 사건이나 결과를 먼저 말한다.
- 첫 몇 단어만 들어도 "뭐지?"라는 궁금증이 생겨야 한다.
- Hook에서 모든 답을 설명하지 않는다.
- 자세한 이유와 근거는 다음 Scene에서 설명한다.
- 자극을 위해 사실을 왜곡하거나 과장하지 않는다.
- 불필요한 수식어, 인사, 반복, 배경 설명을 제거한다.
- 짧게 만들기 위해 핵심 사실이나 의미를 삭제하지 않는다.

예:

약함:
"중세 기사들이 전쟁터에서 왜 그랬을까요?"

강함:
"기사들은 적을 살려뒀다."

약함:
"바이킹에 대한 재미있는 사실이 있습니다."

강함:
"바이킹 투구엔 뿔이 없었다."

약함:
"이 동물은 놀라운 능력이 있습니다."

강함:
"이 동물은 죽은 척한다."

위 예시는 복사하지 않는다.
각 콘텐츠의 실제 사실에 맞춰 새롭게 작성한다.

12.
Ending Scene에서도 질문의 핵심 의미를
임의로 삭제하지 않는다.

13.
채널별 말투와 분위기는 그대로 유지한다.

History:
역사적 사실과 사건의 원인, 결과를 유지한다.

Animal:
동물의 행동, 특징, 이유, 사실관계를 유지한다.

Science:
생활 속 현상, 원인, 과학적 원리와 결과를 유지한다.

AI:
AI 기술의 기능, 원리, 효과, 수치와 조건을 유지한다.

14.
subtitle은 짧을수록 좋은 것이 아니다.

시청자가 subtitle만 읽었을 때
voice에서 전달하려던 핵심 정보를
놓치지 않는 것이 우선이다.


=====================================================
SUBTITLE FINAL CHECK
=====================================================

각 Scene의 voice와 subtitle을 비교한다.

다음 중 하나라도 해당하면
subtitle을 다시 작성한다.

- voice에 비해 지나치게 짧다.
- 핵심 정보가 빠졌다.
- 원인이 빠졌다.
- 결과가 빠졌다.
- 효과가 빠졌다.
- 수치가 빠졌다.
- 조건이 빠졌다.
- 핵심 행동이 빠졌다.
- voice를 한 단어 또는 짧은 유행어로 대체했다.
- 새로운 광고 문구처럼 작성했다.

최종적으로 다음 질문에 YES가 되어야 한다.

"이 subtitle만 읽어도 voice에서 말한
핵심 사실, 이유, 효과, 수치, 조건을
대부분 이해할 수 있는가?"

YES:
정상

NO:
subtitle을 더 구체적으로 작성한다.

=====================================================
FIRST SCENE / FIRST 1~2 SECONDS
=====================================================

첫 Scene은 전체 영상의 가장 중요한 시청자 확보 구간이다.

첫 Scene은 단순한 소개 장면이나 배경 설명으로 시작하지 않는다.

첫 프레임부터 시청자가
"뭐지?"
"왜 저러지?"
"어떻게 된 거지?"
"결과가 어떻게 되는 거지?"
라는 궁금증을 느낄 수 있는 시각적 상황을 보여준다.

첫 Scene의 imageQueries는
주제를 설명하기 위한 평범한 대표 이미지보다
가장 강한 사건, 행동, 이상 현상, 결과 또는 핵심 대상을
즉시 보여주는 장면을 우선한다.

첫 Scene에서 다음과 같은 느린 도입을 금지한다.

- 단순한 배경 화면
- 주제와 관련된 평범한 사진
- 아무 행동이 없는 인물
- 단순한 제품 또는 사물 정면 사진
- 설명을 듣기 전에는 의미를 알 수 없는 추상적인 이미지
- 이야기의 배경을 설명하기 위한 전경
- "오늘 알아볼 것은..."처럼 정보 전달만 시작하는 장면

첫 Scene은 가능하면
핵심 대상 + 구체적인 행동 또는 이상한 상황
이 한 화면에서 즉시 보이도록 구성한다.


첫 Scene의 script와 visual은 서로 연결되어야 한다.

시청자가 첫 화면만 보았을 때도
"무슨 일이 벌어지고 있는지"를 직관적으로 이해할 수 있어야 한다.

특히 첫 1~2초 안에
영상의 핵심 대상과 핵심 상황이 드러나도록 한다.

첫 Scene은 이후 설명을 위한 준비 화면이 아니다.
첫 Scene 자체가 시청자가 계속 볼 이유를 만들어야 한다.

"구독",
"구독해주세요",
"구독하고",
"다음 영상"
등의 표현을 사용하지 않는다.

/*

function parseJSON(result){

    const text =
        String(result || "")
            .replace(/^```json/i, "")
            .replace(/^```/i, "")
            .replace(/```$/i, "")
            .trim();

    return JSON.parse(text);

}


/*
=====================================================
SCENE NORMALIZER
=====================================================
*/

function normalizeScenes(
    scenes,
    format
){

    if(
        !Array.isArray(scenes)
    ){

        return [];

    }


    return scenes.map(
        scene => {

            const normalized = {

                type:
                    scene?.type || "scene",

                script:
                    String(
                        scene?.script || ""
                    ),

                tts:
                    String(
                        scene?.tts ||
                        scene?.script ||
                        ""
                    ),

                subtitle:
                    String(
                        scene?.subtitle || ""
                    ),

                coreSubject:
                    String(
                        scene?.coreSubject || ""
                    ).trim(),

                visualType:
                    "scene",

                imageQueries:
                    Array.isArray(
                        scene?.imageQueries
                    )
                        ? scene.imageQueries
                            .map(
                                item =>
                                    String(item || "")
                            )
                            .filter(Boolean)
                        : [],

                direction:
                    [
                        "hook",
                        "problem",
                        "emotion",
                        "reveal",
                        "detail",
                        "comparison",
                        "cta",
                        "ending"
                    ].includes(
                        scene?.direction
                    )
                        ? scene.direction
                        : (
                            scene?.type === "ending"
                                ? "ending"
                                : "detail"
                        ),

                shot:
                    [
                        "close_up",
                        "medium",
                        "wide",
                        "overhead",
                        "low_angle",
                        "high_angle"
                    ].includes(
                        scene?.shot
                    )
                        ? scene.shot
                        : "medium",

                cameraMove:
                    [
                        "push_in",
                        "pull_out",
                        "pan_left",
                        "pan_right",
                        "tilt_up",
                        "tilt_down",
                        "static"
                    ].includes(
                        scene?.cameraMove
                    )
                        ? scene.cameraMove
                        : "static",

                motion:
                    String(
                        scene?.motion ||
                        "static"
                    ),

                transition:
                    [
                        "cut",
                        "fade",
                        "flash",
                        "slide",
                        "zoom"
                    ].includes(
                        scene?.transition
                    )
                        ? scene.transition
                        : "cut",

                duration:
                    Number(
                        scene?.duration
                    ) > 0
                        ? Number(scene.duration)
                        : 5,

                sceneType:
                    format

            };


            return normalized;

        }
    );

}


/*
=====================================================
DIRECTOR SCENE SAFETY VALIDATION
=====================================================

Scene 하나라도 시각자료를 확보할 수 없는 경우
전체 Director 결과를 실패 처리한다.

절대로 임의의 coreSubject나 imageQuery를
만들어서 통과시키지 않는다.
=====================================================
*/

function validateSceneSafety(
    scenes
){

    if(
        !Array.isArray(scenes) ||
        scenes.length === 0
    ){

        throw new Error(
            "[AI DIRECTOR] FAILED : NO SCENES"
        );

    }


    for(
        let i = 0;
        i < scenes.length;
        i++
    ){

        const scene =
            scenes[i];

        const sceneNumber =
            i + 1;


        if(
            !Array.isArray(
                scene?.imageQueries
            )
        ){

            throw new Error(
                `[AI DIRECTOR] FAILED : SCENE ${sceneNumber} HAS NO IMAGE QUERIES`
            );

        }


        if(
            scene.imageQueries.length < 2
        ){

            throw new Error(
                `[AI DIRECTOR] FAILED : SCENE ${sceneNumber} IMAGE QUERIES LESS THAN 2`
            );

        }


        if(
            scene.imageQueries.length > 3
        ){

            throw new Error(
                `[AI DIRECTOR] FAILED : SCENE ${sceneNumber} IMAGE QUERIES MORE THAN 3`
            );

        }


        for(
            const query of scene.imageQueries
        ){

            const text =
                String(
                    query || ""
                ).trim();


            if(
                !text
            ){

                throw new Error(
                    `[AI DIRECTOR] FAILED : SCENE ${sceneNumber} HAS EMPTY IMAGE QUERY`
                );

            }

}

    }


    return true;

}


/*
=====================================================
DIRECTOR
=====================================================
*/


function coreSubjectMatchesQuery(
    coreSubject = "",
    query = ""
){

    const words =
        String(coreSubject || "")
            .toLowerCase()
            .replace(/\s+/g, " ")
            .trim()
            .split(/\s+/)
            .filter(
                word =>
                    word.length > 2
            );

    const text =
        String(query || "")
            .toLowerCase()
            .replace(/\s+/g, " ")
            .trim();

    if(
        !words.length ||
        !text
    ){
        return false;
    }

    let matched = 0;

    for(
        const word of words
    ){

        if(
            text.includes(word)
        ){

            matched++;

        }

    }

    const required =
        words.length <= 3
            ? words.length
            : 2;

    return matched >= required;

}

=====================================================

3.

voice가 전달하는 핵심 정보의 70~90% 이상을

subtitle에서도 같은 수치를 유지한다.

subtitle에서도 같은 조건과 상황을 유지한다.

7.

11.
HOOK ABSOLUTE RULE

Hook은 설명의 시작이 아니다.
첫 1~2초 안에 시청자의 스크롤을 멈추게 만드는
가장 강한 한 문장이다.

- Hook은 반드시 1문장이다.
- 1~2초 안에 음성으로 전달할 수 있을 정도로 짧게 작성한다.
- 가능하면 10~15자 내외로 작성한다.
- 길어도 20자 안팎을 넘기지 않는다.
- 첫 3~5단어 안에 사건, 결과, 반전, 의외의 사실 또는 강한 궁금증을 배치한다.
- 시대, 장소, 배경, 인물 설명부터 길게 시작하지 않는다.
- "오늘은 ~", "많은 사람들이 ~", "여러분은 알고 계셨나요?" 같은 상투적인 도입을 금지한다.
- 가능한 경우 배경보다 사건이나 결과를 먼저 말한다.
- 첫 몇 단어만 들어도 "뭐지?"라는 궁금증이 생겨야 한다.
- Hook에서 모든 답을 설명하지 않는다.
- 자세한 이유와 근거는 다음 Scene에서 설명한다.
- 자극을 위해 사실을 왜곡하거나 과장하지 않는다.
- 불필요한 수식어, 인사, 반복, 배경 설명을 제거한다.
- 짧게 만들기 위해 핵심 사실이나 의미를 삭제하지 않는다.

예:

약함:
"중세 기사들이 전쟁터에서 왜 그랬을까요?"

강함:
"기사들은 적을 살려뒀다."

약함:
"바이킹에 대한 재미있는 사실이 있습니다."

강함:
"바이킹 투구엔 뿔이 없었다."

약함:
"이 동물은 놀라운 능력이 있습니다."

강함:
"이 동물은 죽은 척한다."

위 예시는 복사하지 않는다.
각 콘텐츠의 실제 사실에 맞춰 새롭게 작성한다.

12.
Ending Scene에서도 질문의 핵심 의미를
임의로 삭제하지 않는다.

13.
채널별 말투와 분위기는 그대로 유지한다.

History:
역사적 사실과 사건의 원인, 결과를 유지한다.

Animal:
동물의 행동, 특징, 이유, 사실관계를 유지한다.

Science:
생활 속 현상, 원인, 과학적 원리와 결과를 유지한다.

AI:
AI 기술의 기능, 원리, 효과, 수치와 조건을 유지한다.

14.
subtitle은 짧을수록 좋은 것이 아니다.

시청자가 subtitle만 읽었을 때
voice에서 전달하려던 핵심 정보를
놓치지 않는 것이 우선이다.


=====================================================
SUBTITLE FINAL CHECK
=====================================================

각 Scene의 voice와 subtitle을 비교한다.

다음 중 하나라도 해당하면
subtitle을 다시 작성한다.

- voice에 비해 지나치게 짧다.
- 핵심 정보가 빠졌다.
- 원인이 빠졌다.
- 결과가 빠졌다.
- 효과가 빠졌다.
- 수치가 빠졌다.
- 조건이 빠졌다.
- 핵심 행동이 빠졌다.
- voice를 한 단어 또는 짧은 유행어로 대체했다.
- 새로운 광고 문구처럼 작성했다.

최종적으로 다음 질문에 YES가 되어야 한다.

"이 subtitle만 읽어도 voice에서 말한
핵심 사실, 이유, 효과, 수치, 조건을
대부분 이해할 수 있는가?"

YES:
정상

NO:
subtitle을 더 구체적으로 작성한다.



=====================================================
CORE SUBJECT — OPTIONAL VISUAL PRIORITY RULE
=====================================================

coreSubject는 모든 Scene에 반드시 존재해야 하는 필드가 아니다.

Scene에 명확한 대표 역사적 대상, 인물, 집단 또는 사건이 있는 경우에는
그 대상을 coreSubject로 지정한다.

coreSubject는 해당 Scene에서 화면으로 우선 보호해야 하는
대표 시각 대상이다.

반대로 Scene의 핵심이 특정 하나의 역사적 주체가 아니라
장소, 건축물, 배경, 환경, 행동, 사건의 분위기,
전투 현장, 행렬, 시장, 궁궐 내부 등의 시각적 상황인 경우에는
coreSubject를 빈 문자열로 둔다.

coreSubject가 없다고 해서 Scene을 실패 처리하지 않는다.

모든 Scene은 반드시 하나의 명확한
coreSubject를 가져야 한다.

coreSubject는 해당 Scene에서
화면으로 반드시 보여줘야 하는
가장 중요한 역사적 대상, 인물, 집단 또는 사건이다.

coreSubject는 짧고 명확한 시각적 대상이어야 한다.

중요:

coreSubject에 불필요한 행동,
장소,
카메라 연출,
긴 상황 설명을 넣지 않는다.

행동, 장소, 상황, 복장, 표정,
시간대 등의 세부 정보는
imageQueries에서 추가한다.


=====================================================
CORE SUBJECT SPECIFICITY
=====================================================

coreSubject는 검색 가능한 구체적인 대상이어야 한다.

단순한 상위 개념을 사용하지 않는다.

금지:

woman
man
person
soldier
building
ship
animal
warrior
historical figure

가능하면 역사적 시대와 문화권을
시각적으로 구분할 수 있도록 포함한다.

예:

medieval European woman
Joseon Korean nobleman
Joseon Korean gisaeng
Roman gladiator
Viking longship
ancient Egyptian mummy
Napoleonic soldier


=====================================================
CULTURAL / HISTORICAL IDENTITY
=====================================================

역사적 인물이나 장면에서
시대 또는 문화권이 시각적으로 중요한 경우
coreSubject에 반드시 포함한다.

예:

나쁜 예:

woman

좋은 예:

medieval European woman


나쁜 예:

nobleman

좋은 예:

Joseon Korean nobleman


나쁜 예:

gisaeng

좋은 예:

Joseon Korean gisaeng


나쁜 예:

soldier

좋은 예:

Napoleonic soldier


이 규칙은 역사적 장면이
다른 시대나 문화권의 인물로 잘못 표현되는 것을
방지하기 위한 것이다.


=====================================================
CORE SUBJECT + IMAGE QUERY
=====================================================

모든 imageQueries는
해당 Scene의 coreSubject를
시각적으로 명확하게 표현해야 한다.

단,

imageQuery에 coreSubject의
전체 문자열을 문자 그대로 복사할 필요는 없다.

핵심 의미와 역사적 정체성은 반드시 유지한다.

imageQuery에는 필요에 따라 다음을 추가한다.

coreSubject
+
핵심 행동
+
장소
+
상황
+
필요한 시대적 / 문화적 시각 요소


예:

coreSubject:
Joseon Korean nobleman

허용:

"Joseon Korean nobleman wearing satgat hiding face"

"Joseon nobleman entering traditional Korean tavern"

"Joseon nobleman walking through traditional Korean tavern at night"


coreSubject:
medieval European woman

허용:

"medieval European woman dancing in town square"

"medieval European woman collapsing during dance"

"medieval European woman surrounded by medieval villagers"


=====================================================
CORE SUBJECT IDENTITY PRESERVATION
=====================================================

imageQuery에서 coreSubject의
시대, 문화권, 인물 정체성을 삭제하지 않는다.

예:

coreSubject:
Joseon Korean nobleman

금지:

"nobleman entering tavern"

"man entering tavern"

"European nobleman entering tavern"

"medieval nobleman entering tavern"


coreSubject:
medieval European woman

금지:

"woman dancing"

"medieval woman dancing"

"Asian woman dancing"

"modern woman dancing"


검색어는 핵심 대상의 역사적 정체성을
다른 시대나 문화권으로 변경해서는 안 된다.


=====================================================
CORE SUBJECT FAILURE
=====================================================

coreSubject가 없는 Scene은 정상적으로 허용한다.

coreSubject가 지나치게 일반적이거나
해당 역사적 장면의 시대 / 문화권을
구분할 수 없는 경우 실패 가능한 결과로 만든다.

Director는 시각자료를 찾기 어렵다는 이유로
coreSubject를 더 넓은 개념으로 변경하지 않는다.

검색이 어렵더라도 역사적 정체성을 유지한다.


=====================================================
CORE SUBJECT OUTPUT
=====================================================

모든 Scene에는 반드시 다음 필드를 포함한다.

coreSubject

coreSubject는 실제 이미지와 영상 검색에서
유지해야 하는 핵심 시각 대상이다.

imageQueries는 coreSubject를 기반으로 작성한다.

imageQueries는 coreSubject의
역사적 정체성, 시대, 문화권을 유지하면서
각 Scene의 행동과 상황을 구체적으로 표현한다.

coreSubject가 없거나 불명확한 Scene을
임의로 수정하지 않는다.

그 Scene은 실패 가능한 결과로 만든다.

=====================================================
ENDING 절대규칙
=====================================================

Ending은 단순히
"좋아요와 댓글 남겨주세요"
만 반복하지 않는다.

콘텐츠와 직접 연결되는
짧은 질문을 먼저 만든다.

질문과 연결되게 댓글을 유도한다.
"여러분의 생각을 댓글로 남겨주세요"
"~이라면 어떨지 댓글로 남겨주세요"와 같은
자연스러운 댓글을 유도한다.

질문 뒤에는
"재미있었다면 좋아요도 눌러주세요."
와 같이 자연스럽게 좋아요를 유도한다.

절대 구독을 유도하지 않는다.

"구독",
"구독해주세요",
"구독하고",
"다음 영상"
등의 표현을 사용하지 않는다.

OUTPUT

[/KEYWORDS]

=====================================================
RECENTLY USED TOPICS — SEMANTIC DUPLICATE CHECK

{{DUPLICATE_TOPICS}}

주제를 선정하기 전에 반드시 기존 주제들을
"의미"와 "핵심 질문" 기준으로 비교한다.


=====================================================
중복 판단 기준
=====================================================

문장이나 제목의 표현이 달라도
다음 조건 중 하나라도 해당하면
같은 콘텐츠 주제로 판단한다.

1.
핵심 질문이 동일하다.

2.
설명하려는 핵심 현상이 동일하다.

3.
핵심 원인 또는 과학적/역사적/동물학적/
기술적 설명 대상이 동일하다.

4.
같은 사건이나 같은 기술 또는 같은 행동을
다른 표현으로 설명한 것뿐이다.

5.
제목의 단어만 바꾸거나
질문 형태만 바꾼 수준이다.

6.
TOP 5와 일반 설명처럼 형식만 다르고
실질적인 콘텐츠 내용이 동일하다.

7.
기존 주제의 일부를 더 자극적인 표현으로
바꾼 것뿐이다.


=====================================================
명백한 의미 중복 예시
=====================================================

기존:
"거울은 왜 좌우만 바뀌고 상하는 안 바뀔까?"

신규:
"거울을 볼 때 왜 좌우만 바뀌고 상하는 그대로일까?"

→ 반드시 중복으로 판단한다.


기존:
"겨울에 문손잡이를 잡으면 왜 찌릿할까?"

신규:
"겨울철 문손잡이를 만질 때 정전기가 발생하는 이유"

→ 반드시 중복으로 판단한다.


기존:
"고양이는 왜 박스를 좋아할까?"

신규:
"집고양이가 작은 상자에 들어가려는 진짜 이유"

→ 반드시 중복으로 판단한다.


기존:
"AI 로봇의 새로운 기능 TOP 5"

신규:
"SF 영화가 현실이 된 AI 로봇의 신기능 TOP 5"

→ 핵심 내용이 동일하다면 중복으로 판단한다.


=====================================================
중요한 구분
=====================================================

단순히 같은 분야나 같은 대상을 다룬다고
무조건 중복으로 판단하지 않는다.

예:

기존:
"AI 로봇의 새로운 기능"

신규:
"AI 로봇이 촉각과 통증을 느끼는 전자 피부"

→ 다른 핵심 기술과 다른 질문이므로
중복으로 판단하지 않는다.


기존:
"고양이가 박스를 좋아하는 이유"

신규:
"고양이가 집사의 얼굴을 핥는 이유"

→ 같은 고양이 콘텐츠지만
핵심 행동과 질문이 다르므로
중복으로 판단하지 않는다.


기존:
"거울이 좌우를 바꿔 보이게 하는 이유"

신규:
"거울의 상이 실제보다 크게 보이는 이유"

→ 핵심 현상이 다르면 중복으로 판단하지 않는다.


=====================================================
주제 선정 절차
=====================================================

반드시 다음 순서로 판단한다.

1.
Manager Keywords를 분석한다.

2.
완성할 수 있는 후보 주제를 생각한다.

3.
각 후보를 RECENTLY USED TOPICS와 비교한다.

4.
문자열이 다른지만 확인하지 않는다.

5.
핵심 질문,
핵심 현상,
핵심 원인,
핵심 사건,
핵심 기술,
핵심 행동을 비교한다.

6.
기존 콘텐츠와 사실상 같은 내용을
다른 제목으로 표현한 후보는 제거한다.

7.
기존 주제와 핵심 내용이 명확하게 다른
새로운 후보를 선택한다.


=====================================================
절대 금지
=====================================================

기존 주제의 제목을 조금 바꾸는 방식으로
새로운 주제를 만들지 않는다.

단어 순서 변경,
동의어 변경,
질문형 변경,
TOP 5 추가,
자극적인 표현 추가,
"진짜 이유" 추가,
"충격적인 이유" 추가,
"놀라운 비밀" 추가

만으로 기존 주제를 재사용하지 않는다.


기존 주제와 핵심 내용이 같다면
반드시 다른 주제를 선택한다.


=====================================================
최종 판단 원칙
=====================================================

"사람이 두 영상을 연속으로 봤을 때
같은 내용을 다시 봤다고 느낄 것인가?"

YES
→ 중복

NO
→ 신규 주제


중복 여부가 애매한 경우에는
기존 주제를 다시 사용하는 대신
다른 관점의 주제를 선택한다.

이 키워드는 완성된 주제가 아니다.

먼저 이 키워드에서 만들 수 있는 가장 흥미로운

/*

JSON PARSER

function parseJSON(result){

    const json =
        String(result || "")
            .replace(/^```json/i, "")
            .replace(/^```/i, "")
            .replace(/```$/i, "")
            .trim();

    return JSON.parse(json);

}

function coreSubjectMatchesQuery(
    coreSubject = "",
    query = ""
){

    const words =
        String(coreSubject || "")
            .toLowerCase()
            .replace(/\s+/g, " ")
            .trim()
            .split(/\s+/)
            .filter(
                word =>
                    word.length > 2
            );

    const text =
        String(query || "")
            .toLowerCase()
            .replace(/\s+/g, " ")
            .trim();

    if(
        !words.length ||
        !text
    ){
        return false;
    }

    let matched = 0;

    for(
        const word of words
    ){

        if(
            text.includes(word)
        ){

            matched++;

        }

    }

    /*
    coreSubject 전체 문구를
    검색어에 그대로 넣을 필요는 없다.

    핵심 단어가 하나라도 검색어에 있으면
    Director 검색어 검증을 통과시킨다.

    실제 이미지가 coreSubject에 맞는지는
    Reviewer가 검증한다.
    */

    return matched >= 1;

}

function validateHistorySceneSafety(
    scenes
){
    if(
        !Array.isArray(scenes) ||
        scenes.length === 0
    ){
        console.error(
            "[HISTORY DIRECTOR] FAILED : NO SCENES"
        );

        throw new Error(
            "HISTORY DIRECTOR 결과에 Scene이 없습니다."
        );
    }

    for(
        let i = 0;
        i < scenes.length;
        i++
    ){
        const scene =
            scenes[i];

        const sceneNumber =
            i + 1;

        /*
        =================================================
        CORE SUBJECT
        =================================================

        coreSubject는 선택 필드다.

        명확한 역사적 대표 대상이 있는 경우에는
        해당 대상을 우선 보호한다.

        대표 대상이 없는 Scene에서는
        빈 문자열을 허용한다.

        coreSubject가 없다고 해서
        Scene을 실패 처리하지 않는다.
        */

        const coreSubject =
            String(
                scene?.coreSubject || ""
            ).trim();

        scene.coreSubject =
            coreSubject;

        /*
        =================================================
        IMAGE QUERIES
        =================================================
        */

        if(
            !Array.isArray(
                scene?.imageQueries
            ) ||
            scene.imageQueries.length === 0
        ){
            console.error(
                `[HISTORY DIRECTOR] FAILED : SCENE ${sceneNumber} HAS EMPTY IMAGE QUERY`
            );

            throw new Error(
                `HISTORY_DIRECTOR_SCENE_${sceneNumber}_NO_IMAGE_QUERY`
            );
        }

        const queries =
            scene.imageQueries
                .map(
                    query =>
                        String(
                            query || ""
                        ).trim()
                )
                .filter(Boolean);

        if(
            queries.length === 0
        ){
            console.error(
                `[HISTORY DIRECTOR] FAILED : SCENE ${sceneNumber} HAS EMPTY IMAGE QUERY`
            );

            throw new Error(
                `HISTORY_DIRECTOR_SCENE_${sceneNumber}_EMPTY_IMAGE_QUERY`
            );
        }
    }

    console.log(
        `[HISTORY DIRECTOR] SCENE SAFETY PASS : ${scenes.length} SCENES`
    );

    return true;
}


    validateHistorySceneSafety(
        director.scenes
    );

    return director;

}

IMAGE PRINCIPLE
=====================================================

imageQueries는 대본을 단순 번역한 단어가 아니다.

실제로 이미지 검색했을 때
해당 Scene을 찾을 수 있는
구체적인 영어 검색어를 작성한다.

각 Scene마다
imageQueries는 정확히 3개만 작성한다.

각 검색어는 다음 요소를 중심으로 만든다.

핵심 주제
+
핵심 행동
+
장소 또는 환경

필요한 경우에만
시각적으로 중요한 특징을 추가한다.

예:

"wild lion stalking zebra on African savanna"

"red panda climbing moss covered tree in forest"

"octopus changing color while hiding on coral reef"

나쁜 검색어:

"lion"
"animal"
"wildlife"
"dangerous animal"

같은 Scene의 검색어를
단어만 바꿔 반복하지 않는다.

대본에 없는 행동이나 상황을
검색어에 추가하지 않는다.

검색어의 목적은
실제 Scene에서 필요한 영상을
찾을 수 있는 후보 풀을 만드는 것이다.


=====================================================
ANIMAL IMAGE SAFETY / QUALITY
=====================================================

가능하면 실제 동물,
야생동물,
자연환경,
다큐멘터리 스타일 이미지를 우선한다.

불필요하게 피나 상처 등 잔혹한 이미지를 요구하지 않는다.

동물의 행동을 설명하는 장면을 우선한다.

예:

사냥:
동물이 먹잇감을 추적하는 장면

방어:
동물이 위협에 대응하는 장면

생존:
동물이 환경에 적응하는 장면

능력:
동물의 신체적 특징이나 행동이 잘 보이는 장면



=====================================================
SUBTITLE — VOICE INFORMATION PRESERVATION
=====================================================

subtitle은 voice를 짧은 카피로 요약하는 항목이 아니다.

subtitle은 voice에서 전달하는 핵심 정보를
시청자가 화면만 읽어도 대부분 이해할 수 있도록
보존해서 작성한다.


=====================================================
SUBTITLE INFORMATION RULE
=====================================================

1.
subtitle은 voice의 핵심 의미를 유지한다.

2.
voice에 포함된 다음 정보는 임의로 삭제하지 않는다.

- 핵심 사실
- 원인
- 이유
- 작동 방식
- 행동
- 효과
- 결과
- 수치
- 시간
- 비교
- 조건
- 대상
- 중요한 특징

3.
subtitle의 정보량은 voice의 약 70~90% 수준을 유지한다.

여기서 70~90%는 단순한 글자 수 비율이 아니다.

voice가 전달하는 핵심 정보의 70~90% 이상을
subtitle에서도 전달해야 한다.

4.
voice가

원인 → 결과

구조라면 subtitle에서도
원인과 결과를 모두 유지한다.

5.
voice에 수치가 포함되어 있다면
subtitle에서도 같은 수치를 유지한다.

6.
voice에 조건이나 상황이 포함되어 있다면
subtitle에서도 같은 조건과 상황을 유지한다.

7.
voice의 핵심 효과나 결과를
짧은 감탄사나 한 단어로 대체하지 않는다.

예:

voice:
"구석진 틈새까지 알아서 파고들어
청소 시간이 반으로 줄어듭니다."

금지 subtitle:
"구석진 틈새 순삭"

금지 subtitle:
"청소 끝"

금지 subtitle:
"반으로 줄어듦"

허용 subtitle:
"구석진 틈새까지 알아서 파고들어
청소 시간이 반으로 줄어듭니다."

또는

"구석진 틈새까지 알아서 파고들어
청소 시간을 반으로 줄여줍니다."

8.
voice의 문장을 반드시 그대로 복사할 필요는 없다.

자막에서 읽기 자연스럽도록
조사, 접속어, 반복 표현, 불필요한 수식어는
자연스럽게 다듬을 수 있다.

하지만 핵심 정보가 사라질 정도로
압축해서는 안 된다.

9.
다음과 같은 짧은 표현으로
voice 전체 내용을 대체하지 않는다.

"순삭"
"끝"
"대박"
"콕"
"공감"
"놀랍죠"
"이게 핵심"
"이유는 이것"

10.
subtitle은 voice와 별개의 새로운 카피를
창작하는 항목이 아니다.

voice에서 실제로 말한 내용을 기반으로 작성한다.

11.
HOOK ABSOLUTE RULE

Hook은 설명의 시작이 아니다.
첫 1~2초 안에 시청자의 스크롤을 멈추게 만드는
가장 강한 한 문장이다.

- Hook은 반드시 1문장이다.
- 1~2초 안에 음성으로 전달할 수 있을 정도로 짧게 작성한다.
- 가능하면 10~15자 내외로 작성한다.
- 길어도 20자 안팎을 넘기지 않는다.
- 첫 3~5단어 안에 사건, 결과, 반전, 의외의 사실 또는 강한 궁금증을 배치한다.
- 시대, 장소, 배경, 인물 설명부터 길게 시작하지 않는다.
- "오늘은 ~", "많은 사람들이 ~", "여러분은 알고 계셨나요?" 같은 상투적인 도입을 금지한다.
- 가능한 경우 배경보다 사건이나 결과를 먼저 말한다.
- 첫 몇 단어만 들어도 "뭐지?"라는 궁금증이 생겨야 한다.
- Hook에서 모든 답을 설명하지 않는다.
- 자세한 이유와 근거는 다음 Scene에서 설명한다.
- 자극을 위해 사실을 왜곡하거나 과장하지 않는다.
- 불필요한 수식어, 인사, 반복, 배경 설명을 제거한다.
- 짧게 만들기 위해 핵심 사실이나 의미를 삭제하지 않는다.

예:

약함:
"중세 기사들이 전쟁터에서 왜 그랬을까요?"

강함:
"기사들은 적을 살려뒀다."

약함:
"바이킹에 대한 재미있는 사실이 있습니다."

강함:
"바이킹 투구엔 뿔이 없었다."

약함:
"이 동물은 놀라운 능력이 있습니다."

강함:
"이 동물은 죽은 척한다."

위 예시는 복사하지 않는다.
각 콘텐츠의 실제 사실에 맞춰 새롭게 작성한다.

12.
Ending Scene에서도 질문의 핵심 의미를
임의로 삭제하지 않는다.

13.
채널별 말투와 분위기는 그대로 유지한다.

History:
역사적 사실과 사건의 원인, 결과를 유지한다.

Animal:
동물의 행동, 특징, 이유, 사실관계를 유지한다.

Science:
생활 속 현상, 원인, 과학적 원리와 결과를 유지한다.

AI:
AI 기술의 기능, 원리, 효과, 수치와 조건을 유지한다.

14.
subtitle은 짧을수록 좋은 것이 아니다.

시청자가 subtitle만 읽었을 때
voice에서 전달하려던 핵심 정보를
놓치지 않는 것이 우선이다.


=====================================================
SUBTITLE FINAL CHECK
=====================================================

각 Scene의 voice와 subtitle을 비교한다.

다음 중 하나라도 해당하면
subtitle을 다시 작성한다.

- voice에 비해 지나치게 짧다.
- 핵심 정보가 빠졌다.
- 원인이 빠졌다.
- 결과가 빠졌다.
- 효과가 빠졌다.
- 수치가 빠졌다.
- 조건이 빠졌다.
- 핵심 행동이 빠졌다.
- voice를 한 단어 또는 짧은 유행어로 대체했다.
- 새로운 광고 문구처럼 작성했다.

최종적으로 다음 질문에 YES가 되어야 한다.

"이 subtitle만 읽어도 voice에서 말한
핵심 사실, 이유, 효과, 수치, 조건을
대부분 이해할 수 있는가?"

YES:
정상

NO:
subtitle을 더 구체적으로 작성한다.

=====================================================
CORE SUBJECT — ABSOLUTE RULE
=====================================================

모든 Scene은 반드시 하나의 명확한 핵심 주제(coreSubject)를 가져야 한다.

coreSubject는 해당 Scene에서 반드시 화면으로 보여줘야 하는
가장 중요한 대상 또는 현상이다.

예:

pygmy squirrel
giant Asian hornet
honeybee
AI facial recognition
Roman Colosseum
steam engine


coreSubject는 상위 개념으로 대체하지 않는다.

예:

pygmy squirrel
→ squirrel 로 변경 금지

giant Asian hornet
→ hornet 로 변경 금지

honeybee
→ bee 로 변경 금지


모든 imageQueries는 반드시 coreSubject를 포함해야 한다.

coreSubject가 "pygmy squirrel"이라면

"pygmy squirrel chewing tree bark"
"pygmy squirrel climbing tree"
"pygmy squirrel eating bark"

처럼 작성한다.

다음은 금지한다.

"squirrel"
"animal"
"forest"
"wildlife"


검색어에 coreSubject가 포함되지 않은 경우
그 검색어는 유효하지 않은 것으로 판단한다.


=====================================================
CORE SUBJECT FAILURE
=====================================================

Director가 Scene의 핵심 주제를 명확하게 정의할 수 없는 경우
임의의 다른 대상을 핵심 주제로 만들지 않는다.

coreSubject가 없거나 불명확한 Scene은 실패로 처리한다.

시각자료를 확보하기 어렵다는 이유로
coreSubject를 더 넓은 개념으로 변경하지 않는다.


=====================================================
CORE SUBJECT OUTPUT
=====================================================

모든 Scene에는 반드시 다음 필드를 포함한다.

coreSubject

coreSubject는 실제 이미지와 영상 검색에서
반드시 유지해야 하는 핵심 대상이다.

=====================================================

다음 단어를 절대 포함하지 않는다.

제작
쇼츠 제작

작업지시
지시서
기획서


제목은 시청자가 실제로 클릭하고 싶게 만든다.

=====================================================

=====================================================

=====================================================
SCENE TYPE
=====================================================

GLOBAL:

모든 일반 Scene의 sceneType은

"global"


RANKING:

모든 일반 Scene의 sceneType은

"ranking"


마지막 Scene은 반드시

type: "ending"

이어야 한다.

마지막 Scene의 sceneType은
선택된 format과 동일하게 유지한다.

=====================================================
ENDING 절대규칙
=====================================================

Ending은 단순히
"좋아요와 댓글 남겨주세요"
만 반복하지 않는다.

콘텐츠와 직접 연결되는
짧은 질문을 먼저 만든다.

질문과 연결되게 댓글을 유도한다.
"여러분의 생각을 댓글로 남겨주세요"
"~이라면 어떨지 댓글로 남겨주세요"와 같은
자연스러운 댓글을 유도한다.

질문 뒤에는
"재미있었다면 좋아요도 눌러주세요."
와 같이 자연스럽게 좋아요를 유도한다.

절대 구독을 유도하지 않는다.

"구독",
"구독해주세요",
"구독하고",
"다음 영상"
등의 표현을 사용하지 않는다.

=====================================================
ANIMAL FACT RULE
=====================================================

동물 콘텐츠에서 가장 중요한 것은
흥미보다 사실성이다.

Director는 키워드와 완성 주제의 범위를
끝까지 유지해야 한다.


=====================================================
주제 범위 절대 준수
=====================================================

완성 주제가

사냥,
포식,
위장,
생존,
번식,
사회생활,
지능,
방어,
이동,
극한 환경 적응

중 하나로 정해졌다면

각 Scene의 사례도 반드시
선택된 주제와 직접적으로 연결되어야 한다.


예를 들어:

주제:
"사냥 함정을 파는 동물 TOP 5"

허용:
- 실제로 먹이를 잡기 위해 함정을 만드는 동물
- 먹이를 유인하거나 가두는 구조를 만드는 동물
- 사냥과 직접 연결된 포식 행동

금지:
- 번식을 위해 둥지를 만드는 행동
- 암컷을 유인하기 위한 구조물
- 단순한 방어 행동
- 단순히 신기한 동물
- 주제와 직접 관련 없는 유명 동물


=====================================================
FACTUAL CONSISTENCY
=====================================================

각 순위의 동물과 행동은
실제로 해당 행동을 하는 종이어야 한다.

동물의 행동을 다른 종과 혼동하지 않는다.

인터넷에서 자주 반복되는 잘못된 동물 상식을
사실처럼 사용하지 않는다.


특히 다음을 임의로 만들지 않는다.

- 존재하지 않는 동물 행동
- 존재하지 않는 사냥법
- 존재하지 않는 생존 전략
- 잘못된 서식지
- 잘못된 먹이 관계
- 잘못된 신체 능력
- 과장된 숫자
- 과장된 속도
- 과장된 힘
- 과장된 사냥 성공률


=====================================================
RANKING FACT RULE
=====================================================

Ranking에서는 5개의 사례가
모두 동일한 기준으로 비교되어야 한다.

예:

"함정을 만드는 동물 TOP 5"

라면

5개 모두 실제 사냥 함정을 만드는 동물이어야 한다.

번식 구조물을 만드는 동물을
사냥 함정 사례로 넣지 않는다.


=====================================================
불확실한 사실 처리
=====================================================

어떤 동물 행동이 실제로 존재하는지 확실하지 않다면
그 사례를 사용하지 않는다.

더 확실한 사례로 교체한다.

확실하지 않은 정보를
"전문가들이 인정한",
"세계에서 가장",
"100% 성공",
"절대 빠져나올 수 없는"

등으로 단정하지 않는다.


=====================================================
흥미와 사실성의 우선순위
=====================================================

1. 사실성
2. 주제 적합성
3. 시청자 흥미
4. 자극적인 표현

순서로 판단한다.

흥미롭지만 사실성이 의심되는 사례보다
조금 덜 자극적이어도 확실한 사례를 선택한다.

설명하려는 핵심 현상이 동일하다.

3.
핵심 원인 또는 과학적/역사적/동물학적/
기술적 설명 대상이 동일하다.

4.
같은 사건이나 같은 기술 또는 같은 행동을
다른 표현으로 설명한 것뿐이다.

5.
제목의 단어만 바꾸거나
질문 형태만 바꾼 수준이다.

6.
TOP 5와 일반 설명처럼 형식만 다르고
실질적인 콘텐츠 내용이 동일하다.

7.
기존 주제의 일부를 더 자극적인 표현으로
바꾼 것뿐이다.

function parseJSON(result){

    const json =
        String(result || "")
            .replace(/^```json/i, "")
            .replace(/^```/i, "")
            .replace(/```$/i, "")
            .trim();

    return JSON.parse(json);

}


/*
=====================================================
ANIMAL DIRECTOR SCENE SAFETY
=====================================================
*/

function validateAnimalSceneSafety(
    scenes
){

    if(
        !Array.isArray(scenes) ||
        scenes.length === 0
    ){

        console.error(
            "[ANIMAL DIRECTOR] FAILED : NO SCENES"
        );

        throw new Error(
            "ANIMAL DIRECTOR 결과에 Scene이 없습니다."
        );

    }


    for(
        let i = 0;
        i < scenes.length;
        i++
    ){

        const scene =
            scenes[i];

        const sceneNumber =
            i + 1;


        /*
        =================================================
        CORE SUBJECT
        =================================================
        */

        const coreSubject =
            String(
                scene?.coreSubject || ""
            )
                .replace(/\s+/g, " ")
                .trim();


        if(
            !coreSubject
        ){

            console.error(
                `[ANIMAL DIRECTOR] FAILED : SCENE ${sceneNumber} HAS NO CORE SUBJECT`
            );

            throw new Error(
                `ANIMAL Scene ${sceneNumber} coreSubject가 없습니다.`
            );

        }


        /*
        =================================================
        IMAGE QUERIES
        =================================================
        */

        if(
            !Array.isArray(
                scene?.imageQueries
            ) ||
            scene.imageQueries.length === 0
        ){

            console.error(
                `[ANIMAL DIRECTOR] FAILED : SCENE ${sceneNumber} HAS EMPTY IMAGE QUERY`
            );

            throw new Error(
                `ANIMAL Scene ${sceneNumber} imageQueries가 없습니다.`
            );

        }


        /*
        =================================================
        SEARCH QUERY CLEAN
        =================================================
        */

        const queries =
            scene.imageQueries
                .map(
                    query =>
                        String(
                            query || ""
                        )
                            .replace(/\s+/g, " ")
                            .trim()
                )
                .filter(Boolean);


        if(
            queries.length === 0
        ){

            console.error(
                `[ANIMAL DIRECTOR] FAILED : SCENE ${sceneNumber} HAS EMPTY IMAGE QUERY`
            );

            throw new Error(
                `ANIMAL Scene ${sceneNumber} imageQueries가 비어 있습니다.`
            );

        }


        /*
        =================================================
        CORE SUBJECT SEARCH VALIDATION
        =================================================

        모든 검색어에 coreSubject가 반드시 포함되어야 한다.
        =================================================
        */


        /*
        =================================================
        RANKING QUERY COUNT
        =================================================

        Ranking의 일반 Scene은 정확히 3개.
        Ending은 제외한다.
        =================================================
        */

        if(
            scene?.sceneType === "ranking" &&
            scene?.type !== "ending"
        ){

            if(
                queries.length !== 3
            ){

                console.error(
                    `[ANIMAL DIRECTOR] FAILED : SCENE ${sceneNumber} RANKING QUERY COUNT = ${queries.length}`
                );

                throw new Error(
                    `ANIMAL Ranking Scene ${sceneNumber} imageQueries는 정확히 3개여야 합니다.`
                );

            }

        }


        /*
        =================================================
        GLOBAL QUERY COUNT
        =================================================

        Global도 기본 규칙에 따라 정확히 3개.
        =================================================
        */

        if(
            scene?.sceneType === "global"
        ){

            if(
                queries.length !== 3
            ){

                console.error(
                    `[ANIMAL DIRECTOR] FAILED : SCENE ${sceneNumber} GLOBAL QUERY COUNT = ${queries.length}`
                );

                throw new Error(
                    `ANIMAL Global Scene ${sceneNumber} imageQueries는 정확히 3개여야 합니다.`
                );

            }

        }

    }


    return true;

}

function coreSubjectMatchesQuery(
    coreSubject = "",
    query = ""
){

    const words =
        String(coreSubject || "")
            .toLowerCase()
            .replace(/\s+/g, " ")
            .trim()
            .split(/\s+/)
            .filter(
                word =>
                    word.length > 2
            );

    const text =
        String(query || "")
            .toLowerCase()
            .replace(/\s+/g, " ")
            .trim();

    if(
        !words.length ||
        !text
    ){
        return false;
    }

    let matched = 0;

    for(
        const word of words
    ){

        if(
            text.includes(word)
        ){

            matched++;

        }

    }

    const required =
        words.length <= 3
            ? words.length
            : 2;

    return matched >= required;

}

coreSubject는 영어로 작성한다.

실제 이미지 검색에서 찾을 수 있는
구체적인 핵심 대상이어야 한다.

=====================================================
SUBTITLE — VOICE INFORMATION PRESERVATION
=====================================================

subtitle은 voice를 짧은 카피로 요약하는 항목이 아니다.

subtitle은 voice에서 전달하는 핵심 정보를
시청자가 화면만 읽어도 대부분 이해할 수 있도록
보존해서 작성한다.


=====================================================
SUBTITLE INFORMATION RULE
=====================================================

1.
subtitle은 voice의 핵심 의미를 유지한다.

2.
voice에 포함된 다음 정보는 임의로 삭제하지 않는다.

- 핵심 사실
- 원인
- 이유
- 작동 방식
- 행동
- 효과
- 결과
- 수치
- 시간
- 비교
- 조건
- 대상
- 중요한 특징

3.
subtitle의 정보량은 voice의 약 70~90% 수준을 유지한다.

여기서 70~90%는 단순한 글자 수 비율이 아니다.

voice가 전달하는 핵심 정보의 70~90% 이상을
subtitle에서도 전달해야 한다.

4.
voice가

원인 → 결과

구조라면 subtitle에서도
원인과 결과를 모두 유지한다.

5.
voice에 수치가 포함되어 있다면
subtitle에서도 같은 수치를 유지한다.

6.
voice에 조건이나 상황이 포함되어 있다면
subtitle에서도 같은 조건과 상황을 유지한다.

7.
voice의 핵심 효과나 결과를
짧은 감탄사나 한 단어로 대체하지 않는다.

예:

voice:
"구석진 틈새까지 알아서 파고들어
청소 시간이 반으로 줄어듭니다."

금지 subtitle:
"구석진 틈새 순삭"

금지 subtitle:
"청소 끝"

금지 subtitle:
"반으로 줄어듦"

허용 subtitle:
"구석진 틈새까지 알아서 파고들어
청소 시간이 반으로 줄어듭니다."

또는

"구석진 틈새까지 알아서 파고들어
청소 시간을 반으로 줄여줍니다."

8.
voice의 문장을 반드시 그대로 복사할 필요는 없다.

자막에서 읽기 자연스럽도록
조사, 접속어, 반복 표현, 불필요한 수식어는
자연스럽게 다듬을 수 있다.

하지만 핵심 정보가 사라질 정도로
압축해서는 안 된다.

9.
다음과 같은 짧은 표현으로
voice 전체 내용을 대체하지 않는다.

"순삭"
"끝"
"대박"
"콕"
"공감"
"놀랍죠"
"이게 핵심"
"이유는 이것"

10.
subtitle은 voice와 별개의 새로운 카피를
창작하는 항목이 아니다.

voice에서 실제로 말한 내용을 기반으로 작성한다.

11.
HOOK ABSOLUTE RULE

Hook은 설명의 시작이 아니다.
첫 1~2초 안에 시청자의 스크롤을 멈추게 만드는
가장 강한 한 문장이다.

- Hook은 반드시 1문장이다.
- 1~2초 안에 음성으로 전달할 수 있을 정도로 짧게 작성한다.
- 가능하면 10~15자 내외로 작성한다.
- 길어도 20자 안팎을 넘기지 않는다.
- 첫 3~5단어 안에 사건, 결과, 반전, 의외의 사실 또는 강한 궁금증을 배치한다.
- 시대, 장소, 배경, 인물 설명부터 길게 시작하지 않는다.
- "오늘은 ~", "많은 사람들이 ~", "여러분은 알고 계셨나요?" 같은 상투적인 도입을 금지한다.
- 가능한 경우 배경보다 사건이나 결과를 먼저 말한다.
- 첫 몇 단어만 들어도 "뭐지?"라는 궁금증이 생겨야 한다.
- Hook에서 모든 답을 설명하지 않는다.
- 자세한 이유와 근거는 다음 Scene에서 설명한다.
- 자극을 위해 사실을 왜곡하거나 과장하지 않는다.
- 불필요한 수식어, 인사, 반복, 배경 설명을 제거한다.
- 짧게 만들기 위해 핵심 사실이나 의미를 삭제하지 않는다.

예:

약함:
"중세 기사들이 전쟁터에서 왜 그랬을까요?"

강함:
"기사들은 적을 살려뒀다."

약함:
"바이킹에 대한 재미있는 사실이 있습니다."

강함:
"바이킹 투구엔 뿔이 없었다."

약함:
"이 동물은 놀라운 능력이 있습니다."

강함:
"이 동물은 죽은 척한다."

위 예시는 복사하지 않는다.
각 콘텐츠의 실제 사실에 맞춰 새롭게 작성한다.

12.
Ending Scene에서도 질문의 핵심 의미를
임의로 삭제하지 않는다.

13.
채널별 말투와 분위기는 그대로 유지한다.

History:
역사적 사실과 사건의 원인, 결과를 유지한다.

Animal:
동물의 행동, 특징, 이유, 사실관계를 유지한다.

Science:
생활 속 현상, 원인, 과학적 원리와 결과를 유지한다.

AI:
AI 기술의 기능, 원리, 효과, 수치와 조건을 유지한다.

14.
subtitle은 짧을수록 좋은 것이 아니다.

시청자가 subtitle만 읽었을 때
voice에서 전달하려던 핵심 정보를
놓치지 않는 것이 우선이다.


=====================================================
SUBTITLE FINAL CHECK
=====================================================

각 Scene의 voice와 subtitle을 비교한다.

다음 중 하나라도 해당하면
subtitle을 다시 작성한다.

- voice에 비해 지나치게 짧다.
- 핵심 정보가 빠졌다.
- 원인이 빠졌다.
- 결과가 빠졌다.
- 효과가 빠졌다.
- 수치가 빠졌다.
- 조건이 빠졌다.
- 핵심 행동이 빠졌다.
- voice를 한 단어 또는 짧은 유행어로 대체했다.
- 새로운 광고 문구처럼 작성했다.

최종적으로 다음 질문에 YES가 되어야 한다.

"이 subtitle만 읽어도 voice에서 말한
핵심 사실, 이유, 효과, 수치, 조건을
대부분 이해할 수 있는가?"

YES:
정상

NO:
subtitle을 더 구체적으로 작성한다.

=====================================================
ENDING
=====================================================

Ending의 목적은 댓글 참여 유도다.

질문 뒤에는 반드시
댓글을 남기도록 자연스럽게 유도한다.

예:

"여러분은 이 사실 알고 계셨나요? 댓글로 알려주세요."

"비행기 창문의 이 작은 구멍, 알고 계셨나요? 댓글로 알려주세요."

"여러분도 이런 경험 해본 적 있나요? 댓글로 알려주세요."

Ending에서는 좋아요를 유도하지 않는다.

좋아요 유도는 별도의 CTA Scene에서만 수행한다.

절대 구독을 유도하지 않는다.

=====================================================

=====================================================

어려운 과학 개념은
생활 속 비유나 실제 상황을 이용해 쉽게 설명한다.

정보를 나열하지 않는다.

=====================================================
중복 판단 기준
=====================================================

문장이나 제목의 표현이 달라도
다음 조건 중 하나라도 해당하면
같은 콘텐츠 주제로 판단한다.

1.
핵심 질문이 동일하다.

2.
설명하려는 핵심 현상이 동일하다.

3.
핵심 원인 또는 과학적/역사적/동물학적/
기술적 설명 대상이 동일하다.

4.
같은 사건이나 같은 기술 또는 같은 행동을
다른 표현으로 설명한 것뿐이다.

5.
제목의 단어만 바꾸거나
질문 형태만 바꾼 수준이다.

6.
TOP 5와 일반 설명처럼 형식만 다르고
실질적인 콘텐츠 내용이 동일하다.

7.
기존 주제의 일부를 더 자극적인 표현으로
바꾼 것뿐이다.


=====================================================
명백한 의미 중복 예시
=====================================================

기존:
"거울은 왜 좌우만 바뀌고 상하는 안 바뀔까?"

신규:
"거울을 볼 때 왜 좌우만 바뀌고 상하는 그대로일까?"

→ 반드시 중복으로 판단한다.


기존:
"겨울에 문손잡이를 잡으면 왜 찌릿할까?"

신규:
"겨울철 문손잡이를 만질 때 정전기가 발생하는 이유"

→ 반드시 중복으로 판단한다.


기존:
"고양이는 왜 박스를 좋아할까?"

신규:
"집고양이가 작은 상자에 들어가려는 진짜 이유"

→ 반드시 중복으로 판단한다.


기존:
"AI 로봇의 새로운 기능 TOP 5"

신규:
"SF 영화가 현실이 된 AI 로봇의 신기능 TOP 5"

→ 핵심 내용이 동일하다면 중복으로 판단한다.


=====================================================
중요한 구분
=====================================================

단순히 같은 분야나 같은 대상을 다룬다고
무조건 중복으로 판단하지 않는다.

예:

기존:
"AI 로봇의 새로운 기능"

신규:
"AI 로봇이 촉각과 통증을 느끼는 전자 피부"

→ 다른 핵심 기술과 다른 질문이므로
중복으로 판단하지 않는다.


기존:
"고양이가 박스를 좋아하는 이유"

신규:
"고양이가 집사의 얼굴을 핥는 이유"

→ 같은 고양이 콘텐츠지만
핵심 행동과 질문이 다르므로
중복으로 판단하지 않는다.


기존:
"거울이 좌우를 바꿔 보이게 하는 이유"

신규:
"거울의 상이 실제보다 크게 보이는 이유"

→ 핵심 현상이 다르면 중복으로 판단하지 않는다.


=====================================================
주제 선정 절차
=====================================================

반드시 다음 순서로 판단한다.

1.
Manager Keywords를 분석한다.

2.
완성할 수 있는 후보 주제를 생각한다.

3.
각 후보를 RECENTLY USED TOPICS와 비교한다.

4.
문자열이 다른지만 확인하지 않는다.

5.
핵심 질문,
핵심 현상,
핵심 원인,
핵심 사건,
핵심 기술,
핵심 행동을 비교한다.

6.
기존 콘텐츠와 사실상 같은 내용을
다른 제목으로 표현한 후보는 제거한다.

7.
기존 주제와 핵심 내용이 명확하게 다른
새로운 후보를 선택한다.


=====================================================
절대 금지
=====================================================

기존 주제의 제목을 조금 바꾸는 방식으로
새로운 주제를 만들지 않는다.

단어 순서 변경,
동의어 변경,
질문형 변경,
TOP 5 추가,
자극적인 표현 추가,
"진짜 이유" 추가,
"충격적인 이유" 추가,
"놀라운 비밀" 추가

만으로 기존 주제를 재사용하지 않는다.


기존 주제와 핵심 내용이 같다면
반드시 다른 주제를 선택한다.


=====================================================
최종 판단 원칙
=====================================================

"사람이 두 영상을 연속으로 봤을 때
같은 내용을 다시 봤다고 느낄 것인가?"

YES
→ 중복

NO
→ 신규 주제


중복 여부가 애매한 경우에는
기존 주제를 다시 사용하는 대신
다른 관점의 주제를 선택한다.

이 키워드는 완성된 영상 주제가 아니다.

키워드에서 사람들이 실제 생활에서 경험하거나
검색할 가능성이 있는 궁금증을 찾아내고,
그 뒤에 숨어 있는 과학적 원리를 이용해
하나의 구체적인 생활과학 콘텐츠 주제로 완성한다.

=====================================================
핵심 방향
=====================================================

전문 과학 지식을 설명하기 위해
생활 사례를 억지로 붙이지 않는다.

반대로
생활 속에서 실제로 발생하는 현상을 먼저 찾고
그 현상을 과학적으로 설명한다.

즉,

생활 속 상황
→ 사람들이 느끼는 의문
→ 과학적 원인
→ 쉽게 설명할 수 있는 주제

순서로 판단한다.

=====================================================
주제 선택 기준
=====================================================

다음 우선순위를 따른다.

1. 많은 사람이 경험할 가능성
2. 제목을 봤을 때 궁금증이 생기는 정도
3. 검색할 만한 생활 문제인가
4. 짧은 영상에서 설명 가능한가
5. 과학적으로 설명 가능한가
6. 시각적으로 표현 가능한가
7. 블로그 글로 확장 가능한가

/*
=====================================================
JSON PARSER
=====================================================
*/

function parseJSON(result){

    let json =
        String(result || "")
            .replace(/^```json/i, "")
            .replace(/^```/i, "")
            .replace(/```$/i, "")
            .trim();


    /*
    =====================================================
    JSON CONTROL CHARACTER SAFETY

    Gemini가 JSON 문자열 내부에 실제 줄바꿈,
    탭 등의 제어문자를 넣는 경우가 있다.

    예:

    "subtitle": "첫 번째 줄
    두 번째 줄"

    이런 값은 JSON.parse()에서
    Bad control character 오류가 발생한다.

    문자열 내부의 제어문자만 JSON escape 형태로
    변환한다.

    JSON 구조 자체는 변경하지 않는다.
    =====================================================
    */

    let normalized = "";
    let inString = false;
    let escaped = false;


    for(
        let i = 0;
        i < json.length;
        i++
    ){

        const char =
            json[i];


        if(
            escaped
        ){

            normalized +=
                char;

            escaped =
                false;

            continue;

        }


        if(
            char === "\\"
        ){

            normalized +=
                char;

            escaped =
                true;

            continue;

        }


        if(
            char === '"'
        ){

            normalized +=
                char;

            inString =
                !inString;

            continue;

        }


        if(
            inString
        ){

            if(
                char === "\n"
            ){

                normalized +=
                    "\\n";

                continue;

            }


            if(
                char === "\r"
            ){

                normalized +=
                    "\\r";

                continue;

            }


            if(
                char === "\t"
            ){

                normalized +=
                    "\\t";

                continue;

            }


            const code =
                char.charCodeAt(0);


            if(
                code < 32
            ){

                normalized +=
                    "\\u" +
                    code
                        .toString(16)
                        .padStart(4, "0");

                continue;

            }

        }


        normalized +=
            char;

    }


    try{

        return JSON.parse(
            normalized
        );

    }
    catch(error){

        console.error(
            "[SCIENCE DIRECTOR] JSON PARSE FAILED"
        );

        console.error(
            error.message
        );

        throw error;

    }

}

function validateScienceSceneSafety(
    scenes
){
    if(
        !Array.isArray(scenes) ||
        scenes.length === 0
    ){
        console.error(
            "[SCIENCE DIRECTOR] FAILED : NO SCENES"
        );

        throw new Error(
            "SCIENCE DIRECTOR 결과에 Scene이 없습니다."
        );
    }

    for(
        let i = 0;
        i < scenes.length;
        i++
    ){
        const scene =
            scenes[i];

        const sceneNumber =
            i + 1;

        /*
        =================================================
        CORE SUBJECT
        =================================================

        coreSubject는 선택 필드다.

        대표 대상이 있는 Scene에서는
        해당 대상을 우선 보호한다.

        대표 대상이 없는 Scene에서는
        빈 문자열을 허용한다.

        coreSubject가 없다고 해서
        Scene을 실패 처리하지 않는다.
        */

        const coreSubject =
            String(
                scene?.coreSubject || ""
            ).trim();

        scene.coreSubject =
            coreSubject;

        /*
        =================================================
        IMAGE QUERIES
        =================================================
        */

        if(
            !Array.isArray(
                scene?.imageQueries
            ) ||
            scene.imageQueries.length === 0
        ){
            console.error(
                `[SCIENCE DIRECTOR] FAILED : SCENE ${sceneNumber} HAS EMPTY IMAGE QUERY`
            );

            throw new Error(
                `SCIENCE Scene ${sceneNumber} imageQueries가 없습니다.`
            );
        }

        const queries =
            scene.imageQueries
                .map(
                    query =>
                        String(
                            query || ""
                        ).trim()
                )
                .filter(Boolean);

        if(
            queries.length === 0
        ){
            console.error(
                `[SCIENCE DIRECTOR] FAILED : SCENE ${sceneNumber} HAS EMPTY IMAGE QUERY`
            );

            throw new Error(
                `SCIENCE Scene ${sceneNumber} imageQueries가 비어 있습니다.`
            );
        }
    }

    return true;
}

function coreSubjectMatchesQuery(
    coreSubject = "",
    query = ""
){

    const words =
        String(coreSubject || "")
            .toLowerCase()
            .replace(/\s+/g, " ")
            .trim()
            .split(/\s+/)
            .filter(
                word =>
                    word.length > 2
            );

    const text =
        String(query || "")
            .toLowerCase()
            .replace(/\s+/g, " ")
            .trim();

    if(
        !words.length ||
        !text
    ){
        return false;
    }

    let matched = 0;

    for(
        const word of words
    ){

        if(
            text.includes(word)
        ){

            matched++;

        }

    }

    const required =
        words.length <= 3
            ? words.length
            : 2;

    return matched >= required;

}

즉,

원문 의미
